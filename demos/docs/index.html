Guide

geojson-three renders and edits GeoJSON in three.js and keeps it precise at projected and geocentric coordinate magnitudes. This page covers the concepts and common tasks. The API reference lists every option and method, and is generated from the JSDoc in the source.

Installation

npm install three github:GalFajon/geojson-three

three.js ≥ r160 is a peer dependency, and the library is tested against r187. It ships as plain ES modules with TypeScript declarations in types/, so editors get completions and type checking without a build step.

Quick start

import * as THREE from 'three';
import { OrbitControls } from 'three/addons/controls/OrbitControls.js';
import { GeoJSONGroup } from 'geojson-three';

const renderer = new THREE.WebGLRenderer({ antialias: true, logarithmicDepthBuffer: true });
const scene = new THREE.Scene();
const camera = new THREE.PerspectiveCamera(50, innerWidth / innerHeight, 0.1, 1e6);
camera.up.set(0, 0, 1);                       // projected CRSs are z-up

const geo = new GeoJSONGroup(await (await fetch('parcels.geojson')).json(), {
    style: { fillColor: '#e8e3d3', strokeColor: '#6b6250', fillOpacity: 1 },
});
scene.add(geo);

// frame the data using float64 bounds
const box = geo.getBoundingBox();
const controls = new OrbitControls(camera, renderer.domElement);
controls.target.copy(box.getCenter(new THREE.Vector3()));
camera.position.copy(controls.target).add(new THREE.Vector3(0, -200, 300));

Group structure

GeoJSONGroup is a THREE.Group. You add it to the scene like any object, but keep the group itself at the identity transform.

GeoJSONGroup (Group, identity) ├─ Group per feature with lines or polygons position = float64 anchor │ ├─ LineSegments2 all LineString parts, merged role: 'line' │ ├─ Mesh all polygon fills, merged role: 'fill' │ └─ LineSegments2 all polygon rings as outlines role: 'stroke' └─ Points per (point style, grid cell) role: 'points'

A feature is addressed by its id, or by an internal key when it has none. Multi-part geometries and GeometryCollections stay a single feature, so picking, highlighting and editing work on the whole feature.

Large coordinates

Float32, which GPUs use for vertex data, has 24 significant bits. At an easting of 500 km it can only store positions every 3 cm; at ECEF magnitude (≈ 6.4 × 10⁶ m) every 50 cm. geojson-three avoids the problem with relative-to-centre rendering:

  1. each feature gets an anchor (the float64 centre of its bounds), stored in object.position;
  2. vertices are stored as float32 offsets from that anchor (the subtraction is done in float64);
  3. three.js multiplies camera.matrixWorldInverse × object.matrixWorld in float64 on the CPU, so the large translations cancel before anything is uploaded to the GPU.

No custom shaders or camera tricks are needed. Raycasting also works in float64, because three.js transforms the ray into local space with the inverse world matrix.

Keep anchored objects compact. Below about 10 km of local extent, float32 error stays under 1 mm. Custom shaders must transform by modelViewMatrix, not by modelMatrix and viewMatrix separately.

The precision test shows a 20 mm target at ECEF magnitude: 0.47 nm of vertex error when anchored, 111.7 mm with absolute float32.

Styling

Styles are plain objects merged over DEFAULT_STYLE. You can pass one object for the whole group, or a function that returns a style per feature.

new GeoJSONGroup(data, {
    style: (f) => ({
        lineColor: f.properties.network === 'water' ? '#2563c9' : '#9a6b3f',
        lineWidth: 2,
        dashed: f.properties.status === 'planned',
        dashSize: 2, gapSize: 1,                // CRS units
    }),
    highlightStyle: { lineColor: '#d97706', lineWidth: 4 },
});

Materials are cached by their effective style, so 10,000 features in five colours use five materials. For data that carries its own styling, use simplestyle. It maps the simplestyle-spec properties onto style keys, and you can spread it under your own overrides:

import { simplestyle } from 'geojson-three';
new GeoJSONGroup(data, { style: (f) => ({ ...simplestyle(f), strokeWidth: 1 }) });

Point sizing & batching

Points are drawn as round, screen-aligned discs. By default pointSize is in pixels and stays constant as you zoom. With pointSizeUnits: 'world', pointSize is a diameter in CRS units: points grow as the camera approaches and shrink as it moves away, within pointMinSize and pointMaxSize pixels.

// 1.5 m markers that never shrink below 3 px or grow beyond 40 px
{ pointSizeUnits: 'world', pointSize: 1.5, pointMinSize: 3, pointMaxSize: 40 }

Points from all features are merged into batches, one per combination of point settings (size, units, clamps, outline) and grid cell. Fill colour is stored per vertex, so it does not split batches. Highlighting a point only rewrites its colour. pointCellSize (default 10 km) sets the cell size. Larger cells mean fewer draw calls, smaller cells mean smaller float32 offsets.

Discs are antialiased and have an outline (pointOutlineColor, pointOutlineWidth). Set the colour to null for plain discs. For map symbols, pass any THREE.Texture as pointTexture (an icon from TextureLoader, or a canvas). The image is multiplied by pointColor, so use white to keep its own colours. Sprites are pulled toward the camera by their on-screen radius, so a symbol standing on a surface is not cut in half by it.

const canvas = document.createElement('canvas');            // 64 × 64 map symbol
canvas.width = canvas.height = 64;
drawTreeSymbol(canvas.getContext('2d'));
const tree = new THREE.CanvasTexture(canvas);
tree.colorSpace = THREE.SRGBColorSpace;

new GeoJSONGroup(trees, { style: { pointTexture: tree, pointColor: '#ffffff', pointSize: 22 } });

Extrusion

The extrude style key gives features a height in CRS units along +z. Polygons become solids with a top, a bottom and outward-facing side walls, and lines become vertical walls (the line itself stays at the base). Solids and walls use fillColor and get baked shading, so they read as 3D in a scene without lights. Outlines follow the top, the bottom and the vertical edges.

new GeoJSONGroup(buildings, {
    style: (f) => ({ extrude: f.properties.height ?? 0, fillColor: '#d6d3cd', fillOpacity: 1 }),
});

new GeoJSONGroup(fences, { style: { extrude: 1.8, fillColor: '#c9c3b6', fillOpacity: 1 } });

Invalid polygons

Real data contains self-intersecting rings, holes that cross the outer ring or each other, holes outside their shell and vertices touching other edges. With the default triangulation: 'auto', every polygon is checked first. Valid polygons use earcut. Invalid ones are split at every crossing and triangulated with a constrained Delaunay triangulation, and only the triangles inside the outer ring and outside every hole are kept. Each repair is reported through onWarning.

The check uses a spatial grid, so it stays fast on large rings. Set triangulation: 'earcut' to skip it for data you know is clean, or 'repair' to always use the constrained triangulation.

Geometry objects

Besides plain GeoJSON features, the group holds editable Point, Line and Polygon objects. Their coordinates are ordinary float64 arrays: vectors (one position for a point, a list for a line, the outer ring for a polygon) and holes on polygons. Change them and call update(); only that feature is rebuilt.

import { Point, Line, Polygon } from 'geojson-three';

const wall = geo.addGeometry(new Polygon([[
    [512300, 5102400, 295], [512310, 5102400, 295], [512310, 5102400, 298], [512300, 5102400, 298],
]], { properties: { kind: 'wall' }, style: { fillColor: '#c9c3b6' } }));

wall.calculateArea();          // 30, measured in the wall's own vertical plane
wall.vectors.forEach((v) => (v[2] += 0.5));
wall.update();

const yard = geo.addGeometry(new Polygon([outerRing]));
yard.carveHole(new Polygon([buildingFootprint]));   // true if it fits inside
yard.fillHole(somePointInTheHole);

geo.removeGeometry(wall);

A geometry's id is its key in the group, and an id can only be used once. geometriesFromGeoJSON turns a document into geometry objects, splitting multi-part features into one object per part, and geometriesToGeoJSON writes them back. The group dispatches featureadded, featureupdated and featureremoved events for both kinds of content. The editor demo is built entirely on this API. It covers drawing, vertex and feature dragging, vertex insertion and removal, snapping, delete, import and export, in about 400 lines of demo code.

Measurements

geo.setShowMeasurements(true) labels every segment with its length and every polygon with its area. geometry.setShowMeasurements(true) or geo.setShowMeasurements(true, key) does the same for one feature. Labels are CSS2DObjects, so add a CSS2DRenderer:

import { CSS2DRenderer } from 'three/addons/renderers/CSS2DRenderer.js';

const labels = new CSS2DRenderer();
labels.setSize(innerWidth, innerHeight);
labels.domElement.style.cssText = 'position:absolute;inset:0;pointer-events:none;z-index:0';
renderer.domElement.after(labels.domElement);
// in the render loop
labels.render(scene, camera);

Lengths are 3D, and areas are measured in the polygon's own plane minus its holes. The text format, unit and label element can be changed with the measurements option. Label positions are computed in float64, so they stay on their segments at any coordinate magnitude.

Picking & highlighting

const raycaster = new THREE.Raycaster();
raycaster.params.Line2 = { threshold: 6 };    // px, for fat lines
raycaster.params.Points.threshold = 0.5;      // CRS units

canvas.addEventListener('click', (e) => {
    raycaster.setFromCamera(pointerNdc(e), camera);   // also sets raycaster.camera
    const hit = raycaster.intersectObject(geo, true)[0];
    const picked = geo.featureFromIntersection(hit);  // { key, feature, geometry? } | null
    if (picked) geo.setHighlighted(picked.key, true);
});

hit.point is in world coordinates and accurate to float64, so it can be shown as a surveyed coordinate directly.

Editing & export

const key = geo.addFeature(feature);
geo.updateFeature(key, { ...feature, geometry: newGeometry });  // rebuilds only this feature
geo.removeFeature(key);

const out = geo.toGeoJSON({ bbox: true });

updateFeature is cheap enough to call every frame for live data such as a GNSS rover (see the site plan). toGeoJSON returns the source features unchanged: float64 coordinates, original geometry types, ids, properties and foreign members such as crs. Polygon rings are closed if the source left them open.

Reprojection

RFC 7946 GeoJSON is longitude/latitude in WGS 84. Rendering degrees directly gives a non-metric, distorted scene, so reproject with the transform option. It runs in float64 before anchoring, so it costs no precision.

import proj4 from 'proj4';
const toUtm = proj4('EPSG:4326', '+proj=utm +zone=33 +datum=WGS84 +units=m +no_defs');

new GeoJSONGroup(lonLatData, { transform: ([lon, lat, h]) => [...toUtm.forward([lon, lat]), h] });

transform is also where height corrections belong, for example converting ellipsoidal heights to orthometric heights with a geoid model.

Limits

  • Each line or polygon feature has one anchor. Features that span more than about 10 km lose sub-millimetre precision toward their ends. Split very long features into parts.
  • There is one Group per line or polygon feature, which is comfortable up to a few thousand features. Points are batched and scale to hundreds of thousands.
  • Fat lines have no joins, so very wide lines show small notches at corners.
  • Lines and points use WebGL materials (LineMaterial, ShaderMaterial). WebGPURenderer is not supported yet.
  • Geometry objects are not lossless: geometriesFromGeoJSON splits multi-part features into parts and drops foreign members. Use the feature API when a document must round-trip unchanged.
  • Text labels from properties, line arrows and data-driven style specs are not rendered.
